    Сканирование стороны¶

    Скан одной стороны карты живой камерой выполняет компонент MergenScanView. Он сам управляет камерой и движком, показывает статусы и возвращает результат ровно один раз через onResult.

    Прогрев¶

    Модели загружаются один раз на процесс. Два уровня:

    // Базовый прогрев (движок, без камеры)
MergenSDK.warmUp(license: license)

// Прогрев + упреждающая загрузка MRZ-моделей (для сценариев с verify)
MergenSDK.preload(licenseKey: license)

// С режимом сканирования (с 2.8.0) — то же значение, что в конфигурации сканера
MergenSDK.warmUp(license: license, scanMode: .post)

    // Базовый прогрев (движок, без камеры) — fire-and-forget
Mergen.warmUp(context, license)

// Прогрев + упреждающая загрузка MRZ-моделей (для сценариев с verify)
Mergen.preload(context, license)

// С режимом сканирования (с 2.8.0) — то же значение, что в MergenScanView
Mergen.warmUp(context, license, scanMode = ScanMode.POST)

    Оба вызова идемпотентны. Параметры leanFields / useUnifiedDetector (по умолчанию true) и scanMode (по умолчанию LIVE) должны совпадать с теми, что будут использоваться при сканировании и верификации — иначе прогретый движок не переиспользуется. Для LITE это ещё и экономия памяти: модели распознавания не загружаются. На устройствах с ОЗУ меньше 5 ГБ упреждающая загрузка MRZ-моделей автоматически пропускается (защита от нехватки памяти) — верификация в этом случае догрузит их по требованию.

    Проверка поддержки устройства (Android)¶

    SDK работает на ARM-устройствах (arm64-v8a и с 2.7.0 — 32-битные armeabi-v7a). Проверяйте до открытия сканера:

    if (!Mergen.isDeviceSupported()) {
    val reason = Mergen.unsupportedDeviceReason()   // UnsupportedAbiException? с userMessage
    // покажите reason?.userMessage и предложите альтернативный путь
}

    На iOS отдельная проверка не нужна — все поддерживаемые iPhone (8 / X и новее) 64-битные.

    MergenScanView¶

    SwiftUI; в UIKit оборачивается в UIHostingController.

    MergenScanView(
    side:                MIDSide,                          // .front / .back
    license:             String?              = nil,       // nil → license.json из бандла
    configuration:       MergenScannerConfig  = .init(),   // scanMode, hqCropEnabled, distanceGate… — см. «Конфигурация»
    bboxColor:           String?              = nil,       // hex "RRGGBB"/"RRGGBBAA"
    bboxStyle:           BBoxDrawStyle        = .cornersOnly,
    strokeWidth:         CGFloat              = 3,
    cornerLength:        CGFloat              = 28,
    showGuideFrame:      Bool                 = false,
    progressBottomInset: CGFloat              = 0,
    scanRoi:             CGRect?              = nil,       // перекрывает configuration.scanRoi
    torchOn:             Binding<Bool>?       = nil,       // nil → авто-фонарик SDK
    onState:             ((ScannerFrameState) -> Void)? = nil,  // свой оверлей
    onResult:            @escaping (MergenScanResult) -> Void
)

    Режим сканирования, HQ-кроп и гейт дистанции на iOS задаются полями configuration — отдельных параметров у MergenScanView для них нет:

    MergenScanView(
    side: .front,
    license: license,
    configuration: MergenScannerConfig {
        $0.scanMode        = .post      // .lite / .post / .live (по умолчанию)
        $0.hqCropEnabled   = true       // croppedPhotoHq в результате
        $0.distanceGate    = true       // по умолчанию true
        $0.distanceMinFill = 0.45       // по умолчанию 0.45
    },
    onResult: onResult
)

    Живая проверка стороны включена всегда. С 2.8.0 MergenScanView сам ставит liveVersionProbe = true, как на Android, — значение из configuration игнорируется. При включённом side-gate (enforceSideMatch) «не та сторона» теперь видна сразу: статус .wrongSide и красная рамка до захвата. Раньше на iOS такая сторона отклонялась молча, и .wrongSide не приходил. Без side-gate поведение прежнее.

    Jetpack Compose.

    MergenScanView(
    side                   : MIDSide,                     // FRONT / BACK
    license                : String? = null,              // null → license.json из assets
    bboxColor              : String? = null,              // hex "RRGGBB"/"AARRGGBB"
    bboxStyle              : BBoxDrawStyle = BBoxDrawStyle.CORNERS_ONLY,
    cornerLengthDp         : Float? = null,
    scanSpeed              : ScanSpeed? = null,           // FAST / NORMAL / THOROUGH
    sideGate               : SideGateConfig = SideGateConfig(),
    progressBottomOffsetDp : Float? = null,
    analyzeAnimEnabled     : Boolean = true,
    captureHintsEnabled    : Boolean = true,              // тексты подсказок качества
    useUnifiedDetector     : Boolean = true,
    liveVersionProbeConf   : Float = 0.65f,
    showGuideFrame         : Boolean = false,
    deviceTier             : Int? = null,
    scanRoi                : RectF? = null,
    deferBackMrz           : Boolean = false,
    hqCropEnabled          : Boolean = false,             // 2.8.0: croppedPhotoHq
    torchEnabled           : Boolean? = null,             // null → авто-фонарик SDK
    scanMode               : ScanMode = ScanMode.LIVE,    // 2.8.0: LITE / POST / LIVE
    distanceGate           : Boolean = true,              // 2.8.0: гейт дистанции
    distanceMinFill        : Float = 0.45f,               // 2.8.0
    distanceMaxFill        : Float = 1.0f,                // 2.8.0
    onError                : ((Throwable) -> Unit)? = null,
    onState                : ((ScannerFrameState) -> Unit)? = null,  // свой оверлей
    onResult               : (MergenScanResult) -> Unit,
)

    Живая проверка стороны в MergenScanView на Android включена всегда (как и раньше); liveVersionProbeConf — её порог уверенности.

    Звук затвора. С 2.8.0 Android, как и iOS, играет системный звук затвора на каждом снимке камеры (и один раз при завершении стороны, если она закрылась без снимка).

    side — декларативная подсказка ожидаемой стороны: она сохраняется в MergenScanResult.side и управляет вашими UX-текстами; движок при этом классифицирует фактическую сторону сам (detectedSide). Жёсткое отклонение «не той» стороны включается side-gate'ом (см. «Конфигурация»).

    Когда задан onState, встроенные тексты SDK подавляются, и каждое состояние кадра приходит в вашу лямбду — см. «Свой UI поверх сканера».

    torchEnabled (Android) / torchOn (iOS): null / nil — фонарик включается сам после серии тёмных кадров. Заданное значение — ручное управление (например, своя кнопка): применяется при каждом изменении, и авто-режим больше не вмешивается. Фактическое состояние фонарика приходит событием TorchChanged / .torchChanged.

    scanRoi — оси различаются между платформами

    Зона сканирования задаётся в нормализованных координатах 0…1. Кадр обрезается до детекции: карта вне зоны не находится вовсе, область вне зоны затемняется, результаты остаются в координатах полного кадра. Минимальный размер зоны — 0.15 по каждой оси. На iOS оси экранные (x — горизонталь), на Android — оси буфера анализа (обратные). Одинаковые числа дают разные окна. Эквивалентная пара значений: iOS CGRect(x: 0.05, y: 0.28, width: 0.90, height: 0.44) ≡ Android RectF(0.28f, 0.05f, 0.72f, 0.95f).

    Режимы сканирования: Lite / Post / Live¶

    С 2.8.0 одним параметром scanMode выбирается, когда распознаётся текст. По умолчанию LIVE — поведение прежнее.

    LITE POST LIVE (по умолчанию)
    Кроп, сторона, поколение да да да
    docNumber, pin, mrz в результате стороны нет нет да
    Когда появляются поля распознаёте у себя (на сервере) в verifyCards / verify сразу
    Скорость захвата стороны быстрее всего быстро, без паузы на распознавание как раньше
    Модели распознавания в памяти не загружаются загружаются в фоне загружаются в фоне
    • LITE — только детекция карты, выпрямленный кроп и проверка качества (авто-разворот, палец после кропа). Для интеграторов, которые распознают на своём сервере.
    • POST — стороны снимаются так же быстро, как в LITE, а распознавание выполняется один раз, когда обе стороны сняты: verifyCards / verify распознают сохранённые кропы тем же конвейером, что в LIVE (по одному кадру на сторону). Поэтому verifyCards для таких сканов занимает секунды, а не ~1 мс — вызывайте из фоновой задачи и показывайте индикатор.
    • LIVE — распознавание во время скана с накоплением по нескольким кадрам, поля приходят в результате каждой стороны.

    Передавайте одно и то же значение для обеих сторон и в warmUp / preload. В LITE / POST параметр deferBackMrz не действует. Mergen.verify / MergenSDK.verify по фото из галереи всегда работает как LIVE, независимо от режима сканера.

    В LITE / POST номера в результате стороны нет — это не ошибка

    docNumber == null здесь по замыслу. Если ваш флоу не пускает к обороту без номера лицевой, проверяйте isOcrPending, а не docNumber:

    let canGoToBack = scan.isOcrPending || scan.docNumber != nil

    val canGoToBack = scan.isOcrPending || scan.docNumber != null

    HQ-кроп для отправки на сервер¶

    hqCropEnabled = true (по умолчанию false) добавляет к результату отдельный кроп карты максимального качества — croppedPhotoHq. Обычный croppedPhoto (1280×800) не меняется.

    • Та же карта и та же ориентация, что в croppedPhoto, но в родном разрешении карты в кадре (не меньше 1280×800, длинная сторона до 4096), с полем 2.5 % по краям.
    • Формат — JPEG максимального качества (ByteArray на Android, Data на iOS). Отправляйте как есть: повторное сжатие съест выигрыш. Объём — несколько МБ на сторону; сверьте с лимитами своего сервера.
    • Под флагом каждая сторона закрывается по настоящему снимку камеры в большем разрешении (при useStillCapture = true, по умолчанию) — это немного дольше и требует больше памяти. Разрешение HQ-кропа равно размеру карты на снимке: чем ближе карта, тем крупнее кроп.

    Когда croppedPhotoHq пустой

    Поле может быть null / nil и при включённом флаге: например, если сторона закрылась по запасному кропу. Всегда держите запасной путь на croppedPhoto. Фото из галереи (verify) HQ-кроп не заполняют. На Android MergenIdResult.croppedImageHq не переживает передачу через Intent / Parcel (лимит Binder) — после неё поле null.

    Гейт дистанции¶

    С 2.8.0 сканер не снимает карту, которая слишком далеко (мелко в кадре) или вылезает за рамку сканирования. Пока дистанция не подходит, скан продолжается, а статус — TooFar («поднесите ближе») или TooClose («отодвиньте»).

    Параметр По умолчанию Что делает
    distanceGate true гейт включён; false — прежнее поведение (подсказка без запрета захвата)
    distanceMinFill 0.45 минимальное заполнение для захвата (0.0…0.9); ниже — TooFar
    distanceMaxFill 1.0 максимальное заполнение (0.5…1.0); выше — TooClose. Карта, касающаяся края рамки, — TooClose всегда

    Заполнение — это длина карты относительно наибольшей, что помещается в scanRoi (или в кадр, если зона не задана): 1.0 — карта касается краёв рамки. Текущее значение доступно в ScannerFrameState.cardFill — его можно показать пользователю.

    • Защита от зависания: если «слишком близко» держится непрерывно 8 с, запрет снимается до конца стороны. Для «слишком далеко» такого снятия нет — поднести ближе можно всегда.
    • Не поднимайте distanceMinFill выше ~0.55 без проверки на устройствах: на iPhone 13–15 Pro ближе ~20 см камера не фокусируется.
    • Фото из галереи (verify) гейт не затрагивает.

    Проверка качества: палец на фото и авто-разворот¶

    SDK прогоняет выпрямленный кроп карты через отдельную модель проверки качества. Обе её функции включены по умолчанию.

    Перевёрнутая карта разворачивается сама. Ориентация определяется до распознавания (точность 0.9963 на реальных кропах), и в OCR кроп уходит уже «головой вверх». Раньше перевёрнутый документ стоил повторного прогона всего распознавания — на устройстве это секунды ожидания, — и мог получить неверно определённую сторону.

    Палец не блокирует захват (с 2.8.0). Сторона снимается, даже если модель видит палец на кадрах наведения: ложные срабатывания на живой камере задерживали лицевую сторону до 17 с. Вместо блокировки готовый кроп проверяется ещё раз после съёмки, и результат приходит флагом:

    Поле результата Тип Что означает
    fingerOnPhoto Bool на итоговом кропе этой стороны виден палец
    photoOcclusionNote String? какое поле перекрыто, по-русски: «Палец на зоне: номера документа», «Тень на зоне: фото»; null / nil, если поле назвать не удалось или помехи нет

    Поля есть в MergenScanResult и MergenIdResult обеих платформ. Переснимать ли сторону, решает приложение — например, показать кроп и предложить «переснять», если fingerOnPhoto == true:

    MergenScanView(side: .front, license: license) { scan in
    if scan.fingerOnPhoto {
        askToRetake(scan.photoOcclusionNote ?? "Палец закрывает данные — переснимите сторону")
    } else {
        proceed(scan)
    }
}

    MergenScanView(side = MIDSide.FRONT, license = license) { scan ->
    if (scan.fingerOnPhoto) {
        askToRetake(scan.photoOcclusionNote ?: "Палец закрывает данные — переснимите сторону")
    } else {
        proceed(scan)
    }
}

    Известное ложное срабатывание — чистая карта в густой тени руки. Для фото из галереи то же правило действует в verify: фото не отклоняется из-за пальца, а флаг приходит в frontOcclusion / backOcclusion (см. «Верификация»).

    Как было до 2.8.0

    В 2.6.0–2.7.x палец на данных блокировал захват: рамка краснела, подсказка называла закрытое поле («Уберите палец с номера документа»), статус был Occluded. С 2.8.0 в живом скане этого больше нет: ScanStatus.Occluded / .occluded и isFingerOccluded до захвата не приходят. Кейс Occluded остался в перечислении ScanStatus для совместимости — ветку в when / switch удалять не нужно.

    Проверки тени и грязи в модели есть, но выключены по умолчанию — почему именно, написано в «Конфигурации» вместе со всеми ключами проверки.

    MergenScanResult — результат скана стороны¶

    Поле Тип Что означает
    side MIDSide сторона, объявленная при запуске
    detectedSide MIDSide? сторона, фактически распознанная движком; nil/null — классификатор не сработал
    generation MergenDocGeneration? поколение макета: y2008 / y2017 / y2025
    version String строка версии целиком, например "Front2017"
    docNumber String? номер документа, прочитанный с этой стороны (в LITE / POST — всегда пусто, см. isOcrPending)
    pin String? ПИН (у лицевых 2017/2025 на карте отсутствует)
    mrz String? строки MRZ через \n (только обороты; при deferBackMrz заполняется на этапе verify)
    croppedPhoto UIImage? / Bitmap? кроп карты с коррекцией перспективы, 1280×800; nil при недостаточном качестве
    croppedPhotoHq Data? / ByteArray? 2.8.0 — HQ-кроп (JPEG) при hqCropEnabled = true, иначе nil; см. HQ-кроп
    fingerOnPhoto Bool 2.8.0 — палец на итоговом кропе; скан не задерживался, см. проверку качества
    photoOcclusionNote String? 2.8.0 — какое поле перекрыто на итоговом кропе
    scanMode ScanMode 2.8.0 — режим, в котором снята сторона
    isOcrPending Bool 2.8.0 — сторона снята без распознавания (LITE / POST), поля пусты по замыслу
    hasSideSnapshot Bool пригоден ли результат для быстрого пути verifyCards (~1 мс)

    Готовые признаки для UX:

    • side != detectedSide — «показана не та сторона»;
    • расхождение generation между сторонами — вероятно, две разные карты;
    • fingerOnPhoto — предложить переснять сторону.
    public enum MergenDocGeneration: String { case y2008 = "2008"; case y2017 = "2017"; case y2025 = "2025" }
    • y2008 — ПИН напечатан на лицевой стороне;
    • y2017 — ПИН только в MRZ на обороте;
    • y2025 — обновлённый дизайн, формат MRZ как у 2017.

    Для сериализации используйте rawValue ("2008"…), это стабильный контракт.
