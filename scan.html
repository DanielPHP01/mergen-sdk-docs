    Сканирование стороны¶

    Скан одной стороны карты живой камерой выполняет компонент MergenScanView. Он сам управляет камерой и движком, показывает статусы и возвращает результат ровно один раз через onResult.

    Прогрев¶

    Модели загружаются один раз на процесс. Два уровня:

    // Базовый прогрев (движок, без камеры)
MergenSDK.warmUp(license: license)

// Прогрев + упреждающая загрузка MRZ-моделей (для сценариев с verify)
MergenSDK.preload(licenseKey: license)

    // Базовый прогрев (движок, без камеры) — fire-and-forget
Mergen.warmUp(context, license)

// Прогрев + упреждающая загрузка MRZ-моделей (для сценариев с verify)
Mergen.preload(context, license)

    Оба вызова идемпотентны. Параметры leanFields / useUnifiedDetector (по умолчанию true) должны совпадать с теми, что будут использоваться при сканировании и верификации — иначе прогретый движок не переиспользуется. На устройствах с ОЗУ меньше 5 ГБ упреждающая загрузка MRZ-моделей автоматически пропускается (защита от нехватки памяти) — верификация в этом случае догрузит их по требованию.

    Проверка поддержки устройства (Android)¶

    SDK работает только на 64-битных ARM-устройствах. Проверяйте до открытия сканера:

    if (!Mergen.isDeviceSupported()) {
    val reason = Mergen.unsupportedDeviceReason()   // UnsupportedAbiException? с userMessage
    // покажите reason?.userMessage и предложите альтернативный путь
}

    На iOS отдельная проверка не нужна — все поддерживаемые iPhone (8 / X и новее) 64-битные.

    MergenScanView¶

    SwiftUI; в UIKit оборачивается в UIHostingController.

    MergenScanView(
    side:                MIDSide,                          // .front / .back
    license:             String?              = nil,       // nil → license.json из бандла
    configuration:       MergenScannerConfig  = .init(),   // см. «Конфигурация»
    bboxColor:           String?              = nil,       // hex "RRGGBB"/"RRGGBBAA"
    bboxStyle:           BBoxDrawStyle        = .cornersOnly,
    strokeWidth:         CGFloat              = 3,
    cornerLength:        CGFloat              = 28,
    showGuideFrame:      Bool                 = false,
    progressBottomInset: CGFloat              = 0,
    scanRoi:             CGRect?              = nil,       // перекрывает configuration.scanRoi
    onState:             ((ScannerFrameState) -> Void)? = nil,  // свой оверлей
    onResult:            @escaping (MergenScanResult) -> Void
)

    Jetpack Compose.

    MergenScanView(
    side                   : MIDSide,                     // FRONT / BACK
    license                : String? = null,              // null → license.json из assets
    bboxColor              : String? = null,              // hex "RRGGBB"/"AARRGGBB"
    bboxStyle              : BBoxDrawStyle = BBoxDrawStyle.CORNERS_ONLY,
    cornerLengthDp         : Float? = null,
    scanSpeed              : ScanSpeed? = null,           // FAST / NORMAL / THOROUGH
    sideGate               : SideGateConfig = SideGateConfig(),
    progressBottomOffsetDp : Float? = null,
    analyzeAnimEnabled     : Boolean = true,
    captureHintsEnabled    : Boolean = true,
    useUnifiedDetector     : Boolean = true,
    liveVersionProbeConf   : Float = 0.65f,
    showGuideFrame         : Boolean = false,
    deviceTier             : Int? = null,
    scanRoi                : RectF? = null,
    deferBackMrz           : Boolean = false,
    onError                : ((Throwable) -> Unit)? = null,
    onState                : ((ScannerFrameState) -> Unit)? = null,  // свой оверлей
    onResult               : (MergenScanResult) -> Unit,
)

    side — декларативная подсказка ожидаемой стороны: она сохраняется в MergenScanResult.side и управляет вашими UX-текстами; движок при этом классифицирует фактическую сторону сам (detectedSide). Жёсткое отклонение «не той» стороны включается side-gate'ом (см. «Конфигурация»).

    Когда задан onState, встроенные тексты SDK подавляются, и каждое состояние кадра приходит в вашу лямбду — см. «Свой UI поверх сканера».

    scanRoi — оси различаются между платформами

    Зона сканирования задаётся в нормализованных координатах 0…1. Кадр обрезается до детекции: карта вне зоны не находится вовсе, область вне зоны затемняется, результаты остаются в координатах полного кадра. Минимальный размер зоны — 0.15 по каждой оси. На iOS оси экранные (x — горизонталь), на Android — оси буфера анализа (обратные). Одинаковые числа дают разные окна. Эквивалентная пара значений: iOS CGRect(x: 0.05, y: 0.28, width: 0.90, height: 0.44) ≡ Android RectF(0.28f, 0.05f, 0.72f, 0.95f).

    Кадр-гейт: палец на данных и авто-разворот¶

    Во время наведения SDK раз в 350 мс прогоняет по выпрямленному кропу карты отдельную модель кадр-гейта. Обе её функции включены по умолчанию и видны пользователю.

    Перевёрнутая карта разворачивается сама. Ориентация определяется до распознавания (точность 0.9963 на реальных кропах), и в OCR кроп уходит уже «головой вверх». Раньше перевёрнутый документ стоил повторного прогона всего каскада — на устройстве это секунды ожидания, — и мог получить неверно определённую сторону.

    Палец на данных блокирует захват. Пока помеха видна:

    • рамка карты горит цветом colorFailure (по умолчанию красным) — так же, как при отклонении по стороне документа;
    • messageTitle называет закрытое поле: «Уберите палец с номера документа», «Уберите палец с MRZ», «Уберите палец с фото». Когда поле назвать не удалось — «Уберите палец с документа»;
    • скан не завершается сам собой: захват удерживается, пока палец не уберут.

    Порог выставлен консервативно: на реальных кадрах помеха ловится в 11 случаях из 12, а ложных срабатываний нет ни на 68 чистых кропах, ни на 12 кадрах «карту держат за кромку», ни на 38 лицевых сторонах с портретом — портрет владельца за палец не принимается. Закрытое поле называется верно примерно в 8 случаях из 10.

    Предохранитель: если помеха «видна» непрерывно дольше 20 с, блокировка снимается. Ложное срабатывание не должно превращаться в «документ невозможно отсканировать».

    Проверки тени и грязи в модели есть, но выключены по умолчанию — почему именно, написано в «Конфигурации» вместе со всеми ключами гейта.

    Своему UI помеха доступна тремя способами сразу — они не могут разойтись: статус ScanStatus.Occluded / .occluded, поля кадра isFingerOccluded / isShadowed / occlusionType / occludedFieldId и готовая строка messageTitle.

    Ломающее изменение 2.6.0

    Статус Occluded / .occluded добавлен в существующее перечисление ScanStatus: исчерпывающие when (Kotlin) и switch (Swift) без новой ветки не соберутся. Примеры миграции — в разделе «Состояния и события».

    MergenScanResult — результат скана стороны¶

    Поле Тип Что означает
    side MIDSide сторона, объявленная при запуске
    detectedSide MIDSide? сторона, фактически распознанная движком; nil/null — классификатор не сработал
    generation MergenDocGeneration? поколение макета: y2008 / y2017 / y2025
    version String строка версии целиком, например "Front2017"
    docNumber String? номер документа, прочитанный с этой стороны
    pin String? ПИН (у лицевых 2017/2025 на карте отсутствует)
    mrz String? строки MRZ через \n (только обороты; при deferBackMrz заполняется на этапе verify)
    croppedPhoto UIImage? / Bitmap? кроп карты с коррекцией перспективы; nil при недостаточном качестве
    hasSideSnapshot Bool пригоден ли результат для быстрого пути verifyCards (~1 мс)

    Готовые признаки для UX:

    • side != detectedSide — «показана не та сторона»;
    • расхождение generation между сторонами — вероятно, две разные карты.
    public enum MergenDocGeneration: String { case y2008 = "2008"; case y2017 = "2017"; case y2025 = "2025" }
    • y2008 — ПИН напечатан на лицевой стороне;
    • y2017 — ПИН только в MRZ на обороте;
    • y2025 — обновлённый дизайн, формат MRZ как у 2017.

    Для сериализации используйте rawValue ("2008"…), это стабильный контракт.
