    Состояния и события¶

    Два канала обратной связи во время скана:

    • ScannerFrameState — снимок состояния «каждый кадр»: геометрия, фазы, тексты. Приходит в onState / onFrameState / оверлей-клоужеры / frameState headless-хэндла.
    • ScannerEvent — именованные события «когда что-то произошло»: камера готова, документ найден/потерян, прогресс, результат, ошибка.

    ScannerFrameState¶

    Поле Тип Что означает
    hasCard Bool карта видна в этом кадре
    cardBoundsInView CGRect? / RectF? рамка карты в координатах вью (поворот и заполнение экрана учтены); nil, когда карты нет
    scanRoiInView CGRect? / RectF? активная зона сканирования в координатах вью — ровно то, что видит движок; рекомендуется отрисовывать весь скан
    confidence Float уверенность детекции 0…1
    progress Float прогресс стабилизации захвата 0…1
    messageTitle String короткий статус для пользователя (пустая строка — нечего показывать)
    messageHint String развёрнутая подсказка («поднесите ближе», «слишком темно»…)
    isAnalyzing Bool короткое окно (≈400 мс) определения версии карты — уместна своя анимация «анализ»
    isScanning Bool активное окно сканирования: карта в кадре, гейты не отклонили; шире, чем isAnalyzing
    isFinished Bool пайплайн завершён (успехом или неудачей)
    isPassed Bool завершён успешным захватом; осмыслен только при isFinished
    isCardInGuide / cardInGuide Bool карта перекрывает направляющую рамку ≥ 80 % (при выключенной рамке всегда «в рамке»)
    activeColor / activeColorArgb Color / Int готовый цвет текущего состояния, выведенный из активного ScannerStyle — можно напрямую красить свою рамку
    scanStatus ScanStatus типизированный статус кадра — машиночитаемый эквивалент messageTitle; см. ниже
    isFingerOccluded Bool кадр-гейт видит палец / руку на данных — захват заблокирован, рамка красная
    isShadowed Bool кадр-гейт видит жёсткую тень на карте (проверка выключена по умолчанию — см. «Конфигурация»)
    occludedFieldId Int какое поле закрыто: 6 — номер документа, 12 — MRZ, 100 — фото владельца и т. д.; -1 — назвать не удалось
    occlusionType OcclusionType чем закрыто: FINGER / SHADOW / NONE (iOS .finger / .shadow / .none)

    Пустое значение для инициализации: ScannerFrameState.empty (iOS) / ScannerFrameState.EMPTY (Android).

    Типовая раскладка своей отрисовки:

    нет карты            → рамка colorIdle + приглашение
hasCard && isScanning → рамка активного цвета + progress
isAnalyzing           → анимация «анализ»
activeColor == failure → красная рамка + messageTitle (не та сторона / не KG ID / палец на данных)
isFinished && isPassed → успех: галочка, вибрация, закрытие

    ScanStatus — типизированный статус кадра¶

    scanStatus — машиночитаемая форма ровно той подсказки, которую SDK показал бы сам. Статус и встроенные строки (messageTitle / messageHint / activeColor) резолвятся в одном месте одним каскадом, поэтому разойтись они не могут: приложение может целиком перейти на свои тексты и свою локализацию, не рискуя «двумя голосами».

    За кадр активен ровно один статус — первый сверху, чьё условие выполнено:

    Finished > Capturing
  > WrongSide | NotKgDocument     (отклонение по стороне, удерживается)
  > Analyzing
  > CardOutsideGuide
  > FlipDocument
  > Occluded                      (палец / тень на данных — захват заблокирован)
  > TooClose > TooFar
  > TooBright > TooDark           (TooDark возможен и без карты в кадре)
  > HoldSteady
  > NoCard
    Kotlin Swift Когда
    NoCard .noCard карты в кадре нет (стартовое значение)
    CardOutsideGuide .cardOutsideGuide карта видна, но лежит мимо направляющей рамки
    HoldSteady .holdSteady карта ведётся, всё в порядке — держите так
    Analyzing .analyzing короткое окно разбора стороны и поколения
    WrongSide .wrongSide показана не та сторона, которую ждёт флоу
    NotKgDocument .notKgDocument серия вердиктов «версия неизвестна»
    FlipDocument .flipDocument двусторонний флоу: первая сторона принята, ждём переворот
    Occluded .occluded новое в 2.6.0 — палец или тень на данных, захват заблокирован

    Галерея

    Для фото из галереи то же заслонение приходит в вердикте верификации: VerifyResult.frontOcclusion / backOcclusion (с 2.6.1) — см. Верификация.

    | TooClose / TooFar | .tooClose / .tooFar | дистанция до карты | | TooBright / TooDark | .tooBright / .tooDark | освещение | | Capturing | .capturing | кадр принят, идут съёмка и распознавание | | Finished(success) | .finished(success:) | пайплайн завершён; неудача приходит сюда же |

    Статус уже сглажен SDK: он наследует гистерезисы своих источников (удержание отклонений по стороне, разные пороги входа и выхода у дистанции, дебаунс подсказок, окно анализа). Собственный дебаунс поверх него не нужен и только добавит задержку.

    Две оговорки:

    • NotKgDocument — это прокси по серии неуверенных классификаций, а не классификатор чужих документов: чужой документ чаще вовсе не детектируется как карта и даёт NoCard. Формулируйте текст осторожно.
    • FlipDocument на iOS объявляет ваш флоу (MergenScannerView(awaitingFlip:) или MergenScannerStateHandle.setAwaitingFlip(_:)): шаг переворота идёт при остановленной камере, кадров в этот момент нет. На Android двусторонний режим ведёт сам SDK.

    Ломающее изменение 2.6.0 — новый кейс Occluded / .occluded

    Кейс добавлен в существующее перечисление, поэтому исчерпывающие when (Kotlin) и switch (Swift) перестанут компилироваться, пока в них не появится новая ветка. Это единственное изменение публичного API в 2.6.0.

    Раньше на таких кадрах приходил HoldSteady («держите неподвижно») — при красной рамке и физически заблокированном захвате это прямо вводило пользователя в заблуждение, поэтому кейс и понадобился.

    val hint = when (val s = state.scanStatus) {
    ScanStatus.NoCard      -> "Наведите камеру на документ"
    ScanStatus.TooFar      -> "Поднесите ближе"
    // НОВОЕ в 2.6.0: палец или тень на данных, захват заблокирован
    ScanStatus.Occluded    -> when (state.occlusionType) {
        OcclusionType.FINGER -> "Уберите палец с документа"
        OcclusionType.SHADOW -> "Уберите тень"
        OcclusionType.NONE   -> ""
    }
    is ScanStatus.Finished -> if (s.success) "" else "Не удалось отсканировать"
    else                   -> ""
}

    let hint: String
switch state.scanStatus {
case .noCard: hint = "Наведите камеру на документ"
case .tooFar: hint = "Поднесите ближе"
// НОВОЕ в 2.6.0: палец или тень на данных, захват заблокирован
case .occluded:
    switch state.occlusionType {
    case .finger: hint = "Уберите палец с документа"
    case .shadow: hint = "Уберите тень"
    case .none:   hint = ""
    }
case .finished(let success): hint = success ? "" : "Не удалось отсканировать"
default: hint = ""
}

    Ветка else / default спасает от ошибки компиляции, но не от молчаливого UI: пока Occluded попадает в неё, пользователь при заблокированном захвате не увидит ничего. Минимальный обратно совместимый вариант — оставить общую ветку и смотреть на поля того же кадра (isFingerOccluded, isShadowed); готовая русская строка с названием закрытого поля уже лежит в messageTitle.

    ScannerEvent¶

    Событие Данные Когда
    cameraReady / CameraReady — камера привязана и отдаёт кадры (повторяется после возврата из фона)
    documentDetected / DocumentDetected bounds в координатах вью документ появился в кадре
    DocumentLost (Android) секунды с последнего появления документ пропал и не вернулся за 1.2 с
    processing / Processing progress прогресс изменился на ≥ 0.1 (частота безопасна для UI)
    success / Success результат скана итог — неудачный захват приходит сюда же: проверяйте success у результата
    error / Error ошибка сбой инициализации/рантайма, отказ в доступе к камере

    Где подписываться:

    // Клоужер
MergenScannerView(..., onEvent: { event in ... }) { state in ... }

// Или поток (headless-хэндл и UIKit-контроллер)
for await event in handle.events { ... }

    events — AsyncStream; каждое обращение к свойству создаёт новый стрим — получите его один раз и держите.

    // Клоужер
MergenScannerView(..., onEvent = { event -> ... }, ...)

// Или поток (Compose-вью, XML-вью, headless-хэндл)
scope.launch { handle.events.collect { event -> ... } }

    events — hot Flow: события без активного подписчика теряются — собирайте, пока экран виден.

    Ошибки и проверка устройства¶

    public enum MergenError: Error {
    case licenseEmpty            // «Лицензия не найдена…»
    case engineInitFailed        // «Не удалось инициализировать распознавание…»
    case cameraPermissionDenied  // «Нет доступа к камере…»
    public var userMessage: String { get }   // готовый русский текст
}

    sealed interface MergenException { val userMessage: String }  // готовый русский текст

class CameraPermissionDeniedException : SecurityException, MergenException
class UnsupportedAbiException : IllegalStateException, MergenException {
    val deviceAbis: List<String>
    val supportedAbis: List<String>
}

// Проверка ДО открытия сканера (SDK работает только на 64-битных ARM):
Mergen.isDeviceSupported(): Boolean
Mergen.unsupportedDeviceReason(): UnsupportedAbiException?

    Если приложение управляет разрешениями само (handlePermissionsInternally = false в конфигурации), SDK никогда не показывает системный запрос камеры: при отсутствии разрешения придёт cameraPermissionDenied в onError и событие error.
