    Верификация двух сторон¶

    Сверка лицевой и оборотной стороны выполняется одним вызовом verify. Вход — либо завершённый скан камеры (.scan), либо сырое фото (.image), в любой комбинации.

    Точки входа¶

    // Рекомендуемая: универсальные входы
let result = try await MergenSDK.verify(
    front:   .scan(frontScan),          // или .image(uiImage)
    back:    .scan(backScan),
    license: license,
    strict:  false
)

// По двум фотографиям
let result = try await MergenSDK.verify(front: frontImage, back: backImage, license: license)

// Мгновенная stateless-сверка двух сканов камеры (~1 мс, без повторного OCR)
let result = try await MergenSDK.verifyCards(front: frontScan, back: backScan, license: license)

    // Рекомендуемая: универсальные входы (suspend)
val result = Mergen.verify(
    context = context,
    front   = MergenSideInput.Scan(frontScan),   // или MergenSideInput.Image(bitmap)
    back    = MergenSideInput.Scan(backScan),
    license = license,
    strict  = false,
)

// По двум фотографиям (suspend)
val result = Mergen.verify(context, frontBitmap, backBitmap, license)

// Мгновенная stateless-сверка двух сканов камеры (~1 мс, без повторного OCR)
val result = Mergen.verifyCards(context, frontScan, backScan, license)

    Как выбирается путь в универсальном verify:

    • обе стороны — сканы камеры со снимками (hasSideSnapshot == true) → сначала мгновенная stateless-сверка; если вердикт однозначен (успех или явное несовпадение документов) — он и возвращается; иначе автоматически запускается полный OCR-пайплайн по кропам;
    • любая сторона .image → полный OCR-пайплайн (секунды): вызывайте из фоновой задачи, показывайте индикатор, UI обновляйте на главном потоке.

    strict: true ужесточает вердикт: успех остаётся успехом только при строгом подтверждении «один и тот же документ».

    Тонкая настройка (configure)¶

    Оба verify принимают необязательный блок конфигурации:

    Поле По умолчанию Что делает
    leanFields true читать только номер, ПИН и MRZ
    strictSameDocument false требовать строгий вердикт SAME_DOCUMENT (без допуска на спорное поле)
    retryBudget iOS 15 / Android 12 сколько раз повторно подавать каждое фото в детекцию: больше — выше полнота, медленнее
    debugLogging false подробный лог
    diagnosticCallback nil пошаговая диагностика без персональных данных; вызывается в фоновом потоке
    useUnifiedDetector true должен совпадать со значением в warmUp/preload

    VerifyResult¶

    Поле Тип Что означает
    status VerifyStatus главный вердикт (таблица ниже)
    verifyId String итоговый номер документа после кросс-валидации сторон (пустая строка — недоступен)
    verifyPin String итоговый ПИН после кросс-валидации
    docNumber / pin String? объединённые значения после сверки визуального чтения с MRZ
    mrzDocNumber / mrzPin String? значения, прочитанные из MRZ
    mrzFull String? строки MRZ через \n
    mrzConfirmed Bool MRZ прочитан и контрольные суммы сошлись
    sameDocument SameDocumentVerdict вердикт «одна ли это карта»
    frontIssue / backIssue VerifySideIssue? что не так с конкретной стороной
    frontPhoto / backPhoto UIImage? / Bitmap? выправленные кропы карты — показывайте их, а не исходные фото
    mrzMatch список по-полевое сравнение визуального чтения с MRZ (поле, оба значения, совпадение, чексумма)
    frontDetectedGeneration / backDetectedGeneration MergenDocGeneration? поколение каждой стороны
    generationMismatch пара поколений или nil подсказка «возможно, две разные карты» — трактовать как предупреждение, не как отказ
    message / messageEn String? готовый текст итога (рус/англ); nil при успехе

    Дополнительно на iOS: docBadge / pinBadge (ConfidenceBadge: missing / uncertain / probable / confirmed) — готовые бейджи уверенности для UI, и frontFieldAvailability / backFieldAvailability — какие источники данных физически есть у распознанного поколения (номер на стороне, ПИН на стороне, MRZ).

    Статусы¶

    VerifyStatus:

    iOS Android Смысл
    .verified VERIFIED стороны сверены, MRZ прочитан, контрольные суммы сошлись
    .verifiedVisual VERIFIED_VISUAL стороны совпали по номеру (и ПИН для 2008), MRZ не прочитан — это не отказ
    .failedFront FAILED_FRONT лицевая сторона не прочитана
    .failedBack FAILED_BACK оборотная сторона не прочитана / нет MRZ и согласия сторон
    .failed FAILED несовпадение документов или жёсткий отказ
    .unknown UNKNOWN вердикт не сформирован

    Удобный признак на iOS: status.isSuccess (verified || verifiedVisual).

    VerifySideIssue:

    Значение Смысл
    .wrongSide / WRONG_SIDE в слоте не та сторона (включая случай «оба фото — лицевая»)
    .notRecognized / NOT_RECOGNIZED сторона не распознана как KG ID

    SameDocumentVerdict:

    Значение Смысл
    SAME_DOCUMENT обе стороны одного документа
    SAME_WITH_WARNING совпадение при одном спорном второстепенном поле
    MISMATCH противоречия — вероятно, разные карты
    SINGLE_SIDE сверка по одной стороне невозможна
    UNKNOWN не определено

    Выбор фото из галереи¶

    Готовые хелперы, чтобы не писать обвязку пикеров:

    // SwiftUI-обёртка системного пикера — для .sheet
MergenPhotoPicker { image in
    // image: UIImage? (nil — отмена); закройте sheet сами
}

    // Compose: системный Photo Picker (Android 13+) или GetContent
val openGallery = rememberMergenGalleryLauncher { bitmap ->
    // bitmap: Bitmap? (null — отмена), EXIF-ориентация уже исправлена
}
Button(onClick = openGallery) { Text("Галерея") }

// Вне Compose: декодирование content-URI с EXIF-коррекцией
val bitmap: Bitmap? = Mergen.decodeImage(context, uri)

    Полученное изображение передаётся в verify как .image(...). На экране результата показывайте frontPhoto / backPhoto из вердикта — это выправленная карта, а не исходное фото пользователя.

    Ошибки¶

    catch {
    let text = (error as? MergenError)?.userMessage ?? error.localizedDescription
}

    MergenError: .licenseEmpty, .engineInitFailed, .cameraPermissionDenied — у каждого готовый русский userMessage.

    catch (e: Exception) {
    val text = (e as? MergenException)?.userMessage ?: e.localizedMessage
}

    MergenException — интерфейс с готовым русским userMessage; реализации: CameraPermissionDeniedException, UnsupportedAbiException (с полями deviceAbis / supportedAbis). Пустая лицензия — IllegalStateException, сбой инициализации движка — RuntimeException.
